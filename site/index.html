How it works

From fixture to a
request you can inspect.

Keep your real provider integration in the test. Choose the behavior on the other side.

  1. Set the scene.

    Script a model, a reply, a tool call or a failure.

    .UseChatScenario("greeting", s => s
  .WhenUserContains("hello")
  .Responds("Hello from your test!"))

  2. Make the call.

    Point your provider SDK or IChatClient at the namespaced route.

    POST /openai/v1/chat/completions
→ 200 OK
→ "Hello from your test!"

  3. Check what happened.

    Assert on the reply and the recorded requests.

    var state = await control
  .GetAssertionsAsync();
// state.Matched == 1

Get started

A local server.
Any stack.

On .NET, add it to your Aspire AppHost. Everywhere else, run the Docker image and point your provider SDK at it.

.NET · Aspire

Add it to your AppHost

Aspire starts the packaged .NET server and allocates its endpoint. No container runtime needed.

Terminal 
dotnet add package ManagedCode.LlmTestServer.Aspire
dotnet add package ManagedCode.LlmTestServer.Client
AppHost.cs 
using ManagedCode.LlmTestServer.Aspire;

var builder = DistributedApplication.CreateBuilder(args);
builder.AddLlmTestServer("llm").WithApiKey("test-key");
builder.Build().Run();
ChatTests.cs 
var control = new LlmTestServerClient(
    app.CreateHttpClient("llm", "http"), "test-key");
await control.ConfigureAsync(config => config
    .RequireBearerToken("test-key").UseGpt41Mini()
    .UseChatScenario("greeting", scenario => scenario
        .WhenUserContains("hello").Responds("Hello from your test!")));

using var chat = control.CreateChatClient();
var reply = await chat.GetResponseAsync(
    [new ChatMessage(ChatRole.User, "hello")]);
// reply.Text == "Hello from your test!"

Any language · Docker

Run the container

Python, Node, Go, Java or anything else: the image serves the same provider routes, dashboard and /admin-api. Load fixtures with one request.

Terminal 
docker run --rm -p 8080:8080 \
  -e LlmTestServer__RequiredBearerToken=local-test-key \
  ghcr.io/managedcode/llm-test-server:1.0.0
Configure 
curl http://localhost:8080/admin-api/configure \
  -H 'Authorization: Bearer local-test-key' \
  -H 'Content-Type: application/json' \
  --data '{"requiredBearerToken":"local-test-key",
    "models":[{"id":"gpt-4.1-mini","kind":"chat"}],
    "chatScenarios":[{"id":"greeting","modelId":"gpt-4.1-mini",
      "responses":[{"content":"Hello from LLM Test Server"}]}]}'
test_chat.py 
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8080/openai/v1",
                api_key="local-test-key")
reply = client.chat.completions.create(
    model="gpt-4.1-mini",
    messages=[{"role": "user", "content": "Hi"}])
assert reply.choices[0].message.content == "Hello from LLM Test Server"

A few useful details

Before your first test.

Does it call a live model?

No. The server returns the fixtures configured for your test. It models API behavior so your application can make real HTTP or SDK calls against a local server.

Is it only for .NET?

No. The Docker image serves the same provider routes, dashboard and management API to any language. Point your Python, Node, Go or Java provider SDK at the container and configure fixtures over HTTP.

Do I need Docker?

Not on .NET. The package-owned Aspire integration starts the packaged .NET server and exposes its allocated resource endpoint. For other stacks, the container image is the way in.

Can I keep my provider SDK?

Use the supported routes with the SDKs listed in the operation coverage documentation. Compatibility is verified per operation; check your client version and API requirements.

How are tokens counted?

Usage is deterministic. Text is counted with a tiktoken-compatible tokenizer, so the same request always reports the same input, output, reasoning and cache values. It does not reproduce a provider's billing.

Can tests share a server?

Yes. Create separate test sessions for independent configuration, scenario queues, history and diagnostics. Dispose each session when its test ends.

Is every provider API implemented?

No. Coverage varies by provider. The operation matrix describes the claimed routes, streaming modes and SDK evidence. Provider profiles grow incrementally.

Does this evaluate model quality?

No. It verifies your application's behavior against scripted API fixtures. It does not measure the quality of a live model's answers.
